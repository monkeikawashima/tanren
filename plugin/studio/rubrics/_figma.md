# Figma フェーズの採点基準

HTML フェーズで合格した見た目を、人間がそのまま編集・引き継ぎできる Figma データにできているかを採点する。
見た目の良し悪しは HTML フェーズで採点済みなので、ここでは「合格した見た目が崩れずに移ったか」と「デザイナーが開いて困らない構造か」だけを見る。

## 5項目（各 1〜10）

### 1. 再現度（parity）
`jobs/<id>/shots/final/` の PNG と、Figma の `get_screenshot` を成果物ごとに並べて比べる。

| 点 | 目安 |
|---|---|
| 10 | 並べて違いが見つからない |
| 8 | 字送り・改行位置など、気づく人が限られる差だけ |
| 6 | 書体の置き換え、行間のずれなど、見れば分かる差が1〜2箇所 |
| 4 | レイアウトが変わっている箇所がある |
| 2 | 別物 |

### 2. 構造（structure）
`get_metadata` の XML で確認する。
- 最上位フレーム名が `<id> / <w>x<h>` になっている
- 上から3階層までに既定名（`Frame 12`、`Rectangle 3`、`Group 5`、`div`、`span`）が残っていない
- 縦・横に並んだ要素はオートレイアウトになっている（重ねて配置するデザインを除く）
- テキストがテキストレイヤーのまま（アウトライン化されていない）

10 = 全部満たす。既定名や手置きの並びが残るほど下げる。

### 3. トークン接続（tokens）
`get_variable_defs` と `get_metadata` で確認する。
- `jobs/<id>/tokens.json` の色・余白・角丸が Figma 変数（またはスタイル）として登録されている
- 塗り・線の色がその変数に紐付いている
- テキストにテキストスタイルが当たっている

10 = 直書きの色・文字設定が残っていない。

### 4. 部品化（components）
- 同じ役割で繰り返す要素（ボタン、カード、バナー各サイズの CTA、ロゴ）がコンポーネント＋インスタンスになっている
- brief でデザインシステムのライブラリが指定されていれば、そのコンポーネントを使っている
- バナー・SNS のサイズ展開は、共通要素が同じコンポーネントから来ている

繰り返し要素がない媒体（ポスター1枚など）は、ロゴとテキストスタイルが部品化されていれば 8 以上。

### 5. 整理（organization）
- 「Final」ページにセクションごとに整列している（成果物の並び順は manifest どおり、間隔一定）
- 先頭に「00 Review」フレームがあり、次が書かれている：brief の一文要約、各フェーズの最終スコア、［要コピー］・仮のコピー・仮の画像の一覧、人間への質問、`jobs/<id>/progress.md` の場所
- 作業途中の残骸（非表示レイヤー、空フレーム、キャンバス外の要素）がない

## ハードフェイル
- manifest の成果物に対応するフレームが1つでも欠けている
- 日本語が豆腐（□）や代替フォントで表示されている
- テキストがアウトライン化・画像化されている
- 画像が欠けている（HTML 側が仮素材の仮置きなら、Figma でも同じ仮置きで可）
- 「00 Review」フレームがない

## 合格
5項目すべてが合格点以上、ハードフェイルなし。
