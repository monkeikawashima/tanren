# prototype — 画面遷移できる HTML プロトタイプ（モック）

複数の HTML を相対リンクでつなぎ、タップ・入力・状態の変化まで動くもの。ui.md の観点もすべて適用する。
critic は Playwright で実際にフローを最後まで操作し、user-tester がペルソナでタスクを試す。

## 媒体別の観点
- **フローの完走**：contract に書かれた主要タスク（例：会員登録 → 初回予約）を、最初の画面から最後まで操作だけで終えられるか。
- **戻れる**：どの画面からも、戻る・閉じる・キャンセルの手段があるか。ブラウザの戻るで破綻しないか。
- **状態**：入力中・エラー・送信中・完了・空の状態が、操作に応じて実際に切り替わるか（静止画の並べ置きではなく）。
- **ナビゲーションの一貫性**：全画面で同じ位置に同じナビがあるか。現在地が分かるか。
- **作り込みの深さ**：主要タスクの経路は本物らしく作り込み、それ以外は「この先は対象外」と明示して止めているか（中途半端なダミー画面を作らない）。
- **モバイル**：390 幅で全フローが操作できるか。

## ハードフェイル
- リンク切れがある（機械チェック）
- 主要タスクが操作で完了しない
- 画面遷移で前の画面の入力内容が消え、やり直しになる（contract で保持を求められている場合）
- フォーカスが見えない、Tab で到達できない操作がある
