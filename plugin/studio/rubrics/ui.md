# ui — アプリ画面・Webアプリ・管理画面

対象：モバイルアプリの画面、SaaS の画面、ダッシュボード、フォーム、設定画面、オンボーディング。
critic は Playwright で実際に操作して採点する。

## 媒体別の観点（共通4項目に加えて見る）
- **フロー**：contract に書かれたタスクを、最短何タップ／クリックで終えられるか。迷う分岐がないか。
- **状態**：空・読み込み中・エラー・成功・権限なし・長いテキスト・大量データの各状態が設計されているか（contract で求められた分）。
- **コンポーネントの一貫性**：同じ役割のボタン・入力・カードが同じ見た目か。主ボタンは1画面に1つか。
- **情報密度**：業務画面なら一覧性、消費者向けなら1画面1目的。brief の利用者像に合っているか。
- **入力**：ラベルが入力欄の外にある、エラー文が欄の近くに具体的に出る、必須の表示がある。
- **アクセシビリティ**：Tab で全操作に到達できる、フォーカスが見える、タップ領域 44x44px 以上（モバイル）。

## ハードフェイル
- 主要タスクが操作で完了しない（ボタンが反応しない、遷移しない）
- Tab 移動でフォーカスが見えない
- モバイル幅（375px）で横スクロールが出る
- フォームの入力欄にラベルがない（placeholder だけ）

## 機能性を 8 以上にする条件
- 主ボタンが画面内で最も目立つ
- エラー文が「何が」「どう直せば」を言っている（「エラーが発生しました」だけは不可）
