# designer の手順書（playbook）

designer が制作の前に毎回読む。coach が全案件のログから「一発目で落ちやすいこと」を見つけて追記していく。
採点基準（rubrics）や審美眼（taste）と違い、ここは「どう作るか」の知恵。coach は検証せずに追記してよいが、出典を必ず残す。

## 着手前のチェック
- 一番小さいサイズ（バナー 320x50、モバイル 390 幅）から作り、大きいサイズへ展開する。
- tokens.json の値だけで組めるか先に確かめる。足りない値があれば、使う前に progress.md に理由を書く。
- brief の「一番伝えたいこと」が、どの成果物でも最初に目に入る位置にあるか、作る前に配置を決める。

## 文字組み
日本語のデザインが「何となくダサい」とき、原因は大半がここにある。どの案件でも最初に決める。

### 書体
- brief やブランドの指定を優先する。指定がなければ和文1つ＋欧文1つ（多くても2系統）。tokens.json に書き、CSS 変数で使う。
- 指定がないときの候補（Google Fonts。Artifact のプレビューでも読み込める）
  - ゴシック：Noto Sans JP、Zen Kaku Gothic New、IBM Plex Sans JP、BIZ UDPGothic
  - 明朝：Noto Serif JP、Shippori Mincho、Zen Old Mincho
- Google Fonts は `<link>` で読み込み、`display=swap` を付け、使うウェイトだけを指定する。ネットワークのない環境で撮るなら、OFL の書体ファイルを `assets/` に置いて `@font-face` で読む。
- 欧文書体と組むときは欧文を先に書き、和文、総称の順にする（例：`font-family: "欧文書体", "Noto Sans JP", sans-serif;`）。欧文書体だけの指定だと、和文が system フォントに落ちる。
- `<html lang="ja">` を付ける。
- ウェイトは2〜3種類まで。太さで階層を作らない。
- 撮影の機械チェックは、総称だけの指定（`sans-serif` だけ等）と、指定にない書体で表示された文字を不合格にする。

### サイズ
- 本文を基準に、一定の比率（1.25〜1.5）で段階を作る。使うサイズは5〜6段まで。tokens.json に段階として書き、それ以外の値を使わない。
- 見出しと本文の差ははっきり付ける。中途半端な差（本文 16px に見出し 18px など）は、階層が見えずに素人っぽくなる一番の原因。

### 行間・字間・行長
- 和文の本文の行間は 1.7〜1.9、見出しは 1.2〜1.4。
- 本文の字間は 0.02〜0.05em。見出しは `font-feature-settings: "palt"` で詰め、字間は 0〜0.02em。本文には palt をかけない。
- 1行の字数は、本文 30〜40字（モバイルは 18〜24字）。`max-width` は em で決める（和文は 1em がほぼ1字）。
- 本文は左揃え。中央揃えは3行までの見出し・キャッチだけ。

### 改行
- 見出し・キャッチは文節で改行する。`word-break: auto-phrase;` を使い、狙った位置があれば `<wbr>` を入れる。1〜2文字だけの行を作らない。
- 行頭・行末の禁則は `line-break: strict;`。

### 和欧混植
- 数字と英字は欧文書体で組み、和文と大きさ・ベースラインが揃っているかをスクショで確かめる。
- 全角の英数字を使わない。
